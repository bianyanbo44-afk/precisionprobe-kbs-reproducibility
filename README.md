# PrecisionProbe: reproducibility release

This repository contains the code, frozen configurations, derived result tables,
and figure files for:

> **Precision-Conditioned Risk Control for Execution-Semantic Uncertainty in Quantized Code Generation**

The release studies whether disagreement among candidate programs generated by a
quantized code model can support selective code generation at that precision.
It includes two development panels, two crossed validation panels and a Qwen3
confirmation run. The repository is intended to make the reported analyses and
figures inspectable without distributing model weights or private submission
files.

## What is included

- `src/precisionprobe/`: scoring, execution, ranking, inference, and risk-control code.
- `configs/`: frozen panel and analysis configurations.
- `phase4_extension/`: locked protocols, extension analyses and robustness records.
- `runs/`: derived generations, scores, EvalPlus labels, audits, and stability records.
- `results/`: compact summary tables and source-manifest metadata.
- `figures/`: publication figures exported as PDF.
- `scripts/`: analysis and audit entry points.
- `tests/`: unit and integrity tests for the released implementation.

Run manifests, token-confidence JSONL records, compact confidence summaries, and
the frozen phase-4 protocol/extension artifacts are included for auditability.
Server logs, model weights, runtime binaries, and machine-specific credentials
are intentionally omitted; manifest paths are repository-relative and model
hashes remain available for identifying separately obtained weights.

The release does **not** include model weights, API credentials, private author
information, manuscript files, or runtime binaries. Benchmark task definitions
and EvalPlus evaluation code remain governed by their upstream licenses. The
bundled result records are derived artifacts; rerunning model generation is not
required to inspect the reported tables and figures.

## Reproduce the released analyses

Python 3.11 or newer is required; the recorded experiment environment used Python
3.12. Install the pinned dependencies from the repository root (PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe scripts/verify_public_release.py
.\.venv\Scripts\python.exe -m pytest -q
```

The commands below use the bundled records and write to `reproduced/`, leaving
the frozen evidence unchanged. No model download or benchmark execution is
needed for analysis replay:

```powershell
.\.venv\Scripts\python.exe scripts/analyze_rapid_qwen3.py --run-dir runs/rapid_qwen3_confirm60 --output-dir reproduced/qwen3
.\.venv\Scripts\python.exe scripts/analyze_pcqrc_extension.py --output-dir reproduced/extension
.\.venv\Scripts\python.exe scripts/analyze_pcqrc_sensitivity_robustness.py --output reproduced/robustness.json --summary-csv reproduced/robustness_summary.csv
.\.venv\Scripts\python.exe scripts/build_kbs_assets.py
```

On Linux/macOS, use `.venv/bin/python` in place of
`.\.venv\Scripts\python.exe`. Bootstrap and repeated-split analyses take longer
than the checksum check. `build_kbs_assets.py` reads the frozen analyses to rebuild
the five KBS figure files and their summary tables. The older
`generate_pcqrc_figures.py` is retained for the earlier extension figure set.

The model-generation pipeline requires separately obtained model weights and an
isolated execution environment. See the configuration files and each run
manifest for the recorded model identifiers and hashes. The bundled runner is a
convenience guard against accidental unsafe execution, not a security sandbox
for adversarial programs; use WSL2 or Docker with resource and network
isolation for full generation/evaluation runs.

The public release is deliberately platform-neutral: run manifests and
evaluation records use repository-relative paths, so the analyses can be
checked after cloning to any local directory.

## Released evidence

The frozen validation panels contain 164 HumanEval+ tasks for Qwen2.5-Coder and
378 MBPP+ tasks for DeepSeek-Coder, each evaluated at Q4 and Q8. The primary
behavioral-disagreement AUROC values are available in
`results/validation_summary.csv`; the independent Qwen3 confirmation is in
`results/qwen3_replication_summary.csv`. Risk-control sensitivity and stability
records are provided in `results/pcqrc_sensitivity_robustness_summary.csv` and
the corresponding run directories.

| Panel | Role | Tasks | Precisions |
| --- | --- | ---: | --- |
| `quartz_qwen_mbpp` | Development | 378 | Q4, Q8 |
| `quartz_deepseek_humaneval` | Development | 164 | Q4, Q8 |
| `pcqrc_qwen_humaneval` | Crossed validation | 164 | Q4, Q8 |
| `pcqrc_deepseek_mbpp` | Crossed validation | 378 | Q4, Q8 |
| `rapid_qwen3_confirm60` | Confirmation | 60 | Q2, Q4, Q8 |

Each panel provides generation records, task-level scores, evaluation labels,
confidence records, and manifests. `token_confidence_summary.csv` is a compact
view of the corresponding JSONL file, not a replacement for the raw token arrays.
See [DATA_DICTIONARY.md](DATA_DICTIONARY.md) for field definitions and source mapping.

All reported quantities are derived from the files in this repository. A missing
or infeasible risk-control threshold is represented explicitly in the released
records rather than replaced with an imputed value.

## File integrity and provenance

`results/source_manifest.json` records SHA-256 digests of public release files.
`scripts/verify_public_release.py` checks those digests, parses JSON/JSONL, and
verifies protocol locks and token-confidence hashes. `.gitattributes` preserves
exact file bytes across Windows and Unix checkouts.

Absolute local paths were replaced with repository-relative paths; Python
executable paths were replaced with `python`. No experimental numerical values
were changed. `results/publication_transforms.json` maps sanitized records to
their original and public digests. Historical run manifests retain their original
run-time hashes, which can differ from public hashes for sanitized JSON files;
use the public source manifest to verify this release. Model weights and runtime
binaries are external prerequisites, not missing release files.

Use a Git commit URL when citing a fixed snapshot of this repository. This release
does not assign a dataset DOI or assert manuscript acceptance.
